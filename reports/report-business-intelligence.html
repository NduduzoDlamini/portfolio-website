Report

Business Intelligence & Data Analytics

A written breakdown of the approach, key findings, and recommendations from this project.

    Overview

    This project performs exploratory data analysis (EDA) on an e-bike sharing dataset using Microsoft SQL Server (T-SQL). It covers data quality assessment, user behavior, station popularity, net flow balance, and user growth trends across 15,000 trips, 25 stations, and 1,000 users. The goal was to answer practical operational questions: when is demand highest, which stations are under strain, how do members differ from casual riders, and where should rebalancing resources go. The analysis demonstrates advanced SQL techniques including CTEs, window functions, multi-table joins, and date/time functions — all essential for real-world analytics work.

    Key Findings

    Finding 1 — Peak hours follow the commute pattern

    Ride volume concentrates in the morning (7–9 AM) and evening (4–7 PM) windows, with clear spikes during typical commute times. This confirms the system is primarily serving commuter traffic, which has direct implications for bike pre-positioning and rebalancing schedules.

    Finding 2 — Members ride more, and differently, than casual users

    Segmenting by membership level shows that Subscribers take longer and more frequent rides than Casual users. This difference in behavior means the two groups contribute differently to system load and should be handled separately in operational planning.

    Finding 3 — A small number of stations handle the majority of trips

    The top 10 starting stations account for a disproportionately large share of all rides. This concentration means operational effort can be targeted efficiently — rebalancing a handful of high-traffic stations addresses most of the system's imbalance.

    Finding 4 — Several stations have significant net flow imbalance

    Comparing arrivals vs. departures per station revealed stations with large positive net flow (bike surplus) and large negative net flow (bike shortage). These imbalances directly point to where rebalancing is needed.

    Finding 5 — User signups show seasonal growth patterns

    Month-over-month growth in new user signups (calculated with the LAG() window function) shows seasonal variation rather than steady linear growth, which informs membership campaign timing.

    Methodology

    • Data sources: Three tables in the DataAnalysis database — rides (trip-level data), stations (station reference), and users (membership and signup data).
    • Data quality checks: Counted NULLs in key ride columns and identified "false starts" — trips under 2 minutes or with zero distance — to exclude them from behavior analysis
    • Summary statistics: Computed min, max, and average trip distance and duration using DATEDIFF() for duration and CAST for numeric precision.
    • User behavior analysis: Joined rides to users and grouped by membership_level to compare ride volume, average distance, and average duration.
    • Peak hour analysis: Grouped rides by DATEPART(HOUR, start_time) to identify demand windows.
    • Station popularity: Joined rides to stations and ranked with TOP 10 ... ORDER BY.
    • Net flow analysis: Used two CTEs (departures and arrivals) joined to the stations table to compute arrivals − departures per station.
    • User growth trends: Used DATETRUNC(MONTH, created_at) with the LAG() window function and NULLIF() (to prevent divide-by-zero) for month-over-month growth.
    • Validation: Cross-checked row counts across tables and confirmed joins produced no orphaned records.
